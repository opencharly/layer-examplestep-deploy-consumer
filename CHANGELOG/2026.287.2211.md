# 2026.287.2211 — fix(plan): make the deploy-time marker check run, and run it on the VENUE

## Summary

This fixture's **own acceptance check could never execute**. It was authored `context: [deploy]`, and
the check engine activates exactly two contexts — `build` under `charly check box`, `runtime` under
`charly check live` (`sdk/checkkit/checkkit.go` `PlanGrammar.InContext`; `sdk/kit/runner.go`
`ContextSkipReason` is the only caller in the plan walk) — so the step was **skipped in both modes**
and the property the repo documents as its functional evidence (*"the probe marker is present on the
target venue"*) asserted nothing. It is the second of the **two real instances** of
`opencharly/plugin-check#111`; the other (`plugin-kube`'s `kube-nodes-ready`) is handed to the lane
that owns that repo.

Two coupled corrections — **both** are needed for the assertion to be true, not just to run:

1. **`context: [deploy]` → `context: [runtime]`** — the live check mode's context, so the step runs
   at all.
2. **`in_container: false` dropped** — that flag (or `from_host: true`) runs the command as a LOCAL
   process on the machine driving the check (`plugin-command/candy/plugin-command/plugin.go`, the
   `exec.CommandContext(ctx, "sh", "-c", cmd)` branch, versus `cc.Exec().RunCapture(ctx, …)` for the
   default). It coincides with the target only when the check runs *on* the target. The repo's own
   `AGENTS.md` says the fixture proves itself *"deployed to a local/VM target"* — and for a
   `target: vm` reached over SSH, `in_container: false` would have asserted the **operator's**
   `/tmp`, i.e. a false green of exactly the class `#111` is about. The default runs through the
   venue executor, so the assertion holds for `target: local` and `target: vm` alike.

The **`run:` step keeps `context: [deploy]`** — meaningful there: it names the install timeline
(`sdk/deploykit/install_build.go`), and it is what lowers to the `ExternalPluginStep` whose
`OpExecute` writes the marker.

Mirrored in the candy `description:` and this repo's `AGENTS.md` (the *"deploy-context `check:`"*
phrasing and the `in_container: false` claim are corrected, not reasserted).
